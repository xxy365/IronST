## A. 语义正确性

### A1. F5：结构体 `=` / `<>` 的值语义（P0）

- [x] **A1 · 结构体比较按值**（2026-10-23，方案 A，本次提交）

**验收代码**（`f5_acceptance.st`）：

```iecst
TYPE P :
STRUCT
    a : INT;
    b : INT;
END_STRUCT;
END_TYPE;

PROGRAM Main
VAR
    x : P;
    y : P;
END_VAR
x.a := 1;
x.b := 2;
y.a := 1;
y.b := 2;
Print(x = y);       (* 期望 1 *)
Print(x <> y);      (* 期望 0 *)
y.b := 3;
Print(x = y);       (* 期望 0 *)
Print(x <> y);      (* 期望 1 *)
END_PROGRAM
```

**修复后实际结果**：

```text
$ ironst run f5_acceptance.st
1
0
0
1
[run] 执行完成                              # 退出码 0
```

> `verify` 目前不注入 `Print` 宿主，直接验证上面的示例会报 4 个
> `E2006 未声明的函数 'Print'`（这是 C7 独立项，不是结构体比较错误）。
> 去掉 `Print`、只保留比较赋值的版本可 `verify` 通过（0 条诊断，退出码 0）。

**实现（方案 A）**：

1. **前端准入**：`SemanticAnalyzer.InferBinary` → `CheckStructComparison`
   - 只允许 `=` / `<>`；两侧必须是**同一个命名结构体类型**；
   - 两侧必须是可寻址左值（变量、字段、数组元素）；结构体函数返回值等直接拒绝；
   - 递归检查字段：`REFERENCE` / `STRING` / `WSTRING`（含嵌套、数组元素）报 `E2003`；
   - 顶层数组整体比较报 `E2003`（结构体**字段**里的数组仍会逐元素展开）；
   - 全局/外部聚合在 A8 修复后已可比较（此前暂报 `E2003`）。
2. **代码生成**：`ExpressionEmitter.EmitStructComparison`
   - 字节码把结构和数组**扁平化**到 VM 栈槽，寄存器里的“聚合值”不是
     `ValueTag.Struct`，因此不能对结构体整体 `load`/`icmp`；
   - 改为按地址逐字段/逐元素 `GEP + load + icmp/fcmp`，`=` 用 AND 合取、
     `<>` 用 OR 析取；
   - 每个「结构体类型 + 比较方向」生成一个私有 `i1 (ptr, ptr)` helper
     （`__st_cmp_N`），helper 缓存放在 `CodeGenContext`；避免把整棵比较树
     内联到调用者，耗尽 242 个字节码寄存器。
3. **运行时**：未修改 `BcValue.Eq` 的结构体分支。IR 已完全降级为逐字段比较，
   整结构体 `IEQ/BEQ` 对该特性不可达；标量 `BEQ/BNE` 行为不变。
4. **字段顺序**：`TypeMapper` 的 IR 结构体字段按字母序（`Ordinal`），
   helper 递归使用 `StructType.Body.ElementTypes` 的同一顺序，偏移与 IR 布局一致。

**测试证据**：

- `IronST.Frontend.Tests/StructComparisonTests.cs`：**17 例**
  - 成功：同类型 `=`/`<>`、嵌套字段、数组元素、数值/BOOL/REAL/枚举；
  - 拒绝：`<`/`>`/`<=`/`>=`、不同类型、结构体 vs 标量、
    `REFERENCE`/`STRING`/`WSTRING`（含嵌套/数组）、顶层数组、非左值。

### A2. 空引用解引用保护（P0）

- [x] **A2 · `REFERENCE` 为零时给运行时错误，而不是读地址 0**（2026-10-23）

- 现状：`ExpressionEmitter.ApplySuffix` 直接 `load` 指针，不判空。
- 验收：零初始化引用 `p^.field` / `p^` 触发明确 `RuntimeError`（带源位置），
  不返回 0、不越界；非空引用行为不变。
- 证据：`IronST.LLVMCodeGen/CodeGen/ExpressionEmitter.cs:238-241`；
  `docs/待办.md` P1「空引用解引用保护」。
- 落地（关键前提：**引用不是地址，是帧槽号**）：
  1. 新指令 `NULLCK R`（`0x95`，2 字节），紧邻 `BOUNDS`；虚拟机侧按
     `BcValue.Tag == Void` 判空。**不能按数值 0 判** —— 槽 0 是合法槽，
     零初始化的引用是 `Void`，已绑定的指针是 `Int64`。
  2. 新错误类型 `RuntimeErrorType.NullReference`；PC / 源位置由现有错误边界回填。
  3. 代码生成在**解引用点**插入检查：`p^` 读取（通用 `GETR` 前）、`r^ := …`
     写入（通用 `SETR` 前）、`p^.field` / `r^[i]`（通用 `GEP` 前）。
     必须在槽号算术之前判 —— 一旦把 `Void` 当 0 加了偏移，就再也分不出空引用。
  4. **复制空引用不报错**（`q := r`）：报错时机是“解引用”，不是“持有”，否则合法复制会被误伤。
     判据：IR 里只有「指针类型的 `load`」是解引用读出的指针值（绑定写的是常量/寄存器）。
  5. 全链路补齐：`OpCode` / 长度表 / 主循环 / 反汇编 / `BytecodeBuilder` /
     调试文本 / 汇编器发射表（`BytecodeAssemblerTests` 的全量 ISA 遍历会强制要求）。
- 实测（CLI）：
  ```text
  x := r^;   → [NullReference] at 0x20: 空引用解引用：REFERENCE 未绑定或为 NULL（null_read.st:7）
  x := r^.a; → [NullReference] at 0x1A: …（null_field.st:12）
  r^ := 5;   → [NullReference] at 0x1A: …（null_write.st:5）
  ```
  三条均退出码 1；`r REF= i` 后 `r^ := 70` / `out := r^` 正常，退出码 0；`q := r`（复制空引用）也退出码 0。
- 测试：`VMNullCheckTests` 3 例（Void 报错并带 PC / `Int64` 0 不误判 / 源位置）、
  `NullReferenceIntegrationTests` 5 例、`CliNullReferenceTests` 1 例。
  全量：**1928 通过 / 0 跳过 / 0 失败**。
- 已知边界：`VAR_IN_OUT` / 引用参数传入空引用时，判空发生在**被调方解引用**那一刻
  （调用方不报错，错误位置指向被调方那一行）；参数传递本身不插入检查。

### A8. 全局 / 外部聚合存储（P0，本轮新发现）

- [x] **A8 · 全局结构体字段读写必须落到真实存储**（2026-10-23）

- 原状：`VAR_GLOBAL x : P; x.a := 1` 的字节码用**未初始化的基址寄存器**
  （`EnsureReg(GlobalVariable)` 回退）计算字段地址，字段被写进错误的 VM 槽；
  读回“碰巧”一致，但比较、跨 POU 访问会 `SlotOverflow` 或静默读到错误数据。
  当时结构体比较在前端明确拒绝全局/外部聚合（`E2003`）以避开坏路径。
- 落地：
  1. **全局槽按 `FlatSlotCount` 展开**：`BytecodeAssembler.DeclareGlobal(name, slots)`；
     `globalIndex[name]` 记**起始槽号**，标量仍 1 槽 ⇒ 既有程序槽位不变。
     超 `MaxGlobals` 时在编译期按“总槽数”拒绝。
  2. **数组全局的声明类型补上**：`VariableInfo.DeclaredType`（语义层已解析的类型）
     → `IRGenerator.RegisterGlobalVariables`。此前数组全局按显示字符串
     （`ARRAY[0..1] OF P`）反解失败，IR 退化成 `@xs = global i32 0`，
     聚合元素被当成标量。
  3. **地址空间区分**：聚合全局的“值”是起始全局槽号（`LDC`）；
     由它派生的 GEP 登记进 `_globalAddresses`，标量读/写改发
     `GETGI/SETGI`（而不是按帧 FP 寻址的 `GETR/SETR`）。
     聚合全局加入 `IsRematerializable`：它不是 `Instruction`、不会进 spill 候选，
     跨 `CALL` 后必须重新 `LDC`（否则读到被调方残留寄存器，实测 `SlotOverflow`）。
  4. **聚合 load/store**：新增 `AggregateRef`（栈槽 / 全局槽 × 静态 / 运行时地址）与
     `EmitAggregateCopyRefs`。两侧都是编译期栈槽时仍走原来的 `GETL/SETL` 立即数路径
     （字节码逐字节不变）；跨空间或运行时地址时用游标寄存器 `GETGI/GETR` +
     `SETGI/SETR` 逐槽搬运。
  5. **比较辅助函数**：`__st_cmp_N(ptr, ptr)` 在自己的帧里看不到全局寻址，
     调用方先把全局操作数复制到帧内临时区再传（跨帧重定基逻辑不变）。
  6. 前端删除全局/外部聚合比较的拒绝分支。
- 验收：
  - `AggregateStorageIntegrationTests` **10 例**：全局字段/整体赋值、按值比较、
    跨 POU（`VAR_EXTERNAL` 读写）、全局结构体数组动态下标、局部副本不别名、
    以及 A9 的 5 例。
  - `StructComparisonTests.GlobalStructComparison_Compiles` 改为正例。
  - 全量：**1938 通过 / 0 跳过 / 0 失败**。
- 已知边界（另行登记）：
  - `GETGI/SETGI` 不进 `GlobalIdx` 重定位表 ⇒ 含全局聚合动态访问的 `.stmod`
    跨模块链接仍不可用（随 B1/REL-3 一起处理）。
  - 全局聚合传给 `VAR_IN_OUT` / `REFERENCE` 形参仍是“传全局槽号给按帧寻址的
     GETR/SETR”，未验收、未修复。
  - `_nextReg` 只增不减（C8）在聚合副本上更易触发。

### A10. 未赋值 `REAL` 的 `<>` 比较（P0，本轮新发现）

## C. 运行时 / 运维

### C1. 默认执行预算 / `MaxInstructions`（P0）

- [x] **C1 · 无人值守场景不会无限挂起**（2026-10-23，本地改动未提交）

- 现状：`--timeout` 是 opt-in；没有确定性指令预算。
- 验收：提供 `--max-instructions N` 或宿主默认预算；超限报明确错误并退出；
  墙钟超时与指令预算分别测试。
- 备注：上一轮明确“只做 CancellationToken”，本项是后续独立决策。
- **决策：opt-in（默认不限）**。理由：真实 PLC 程序的扫描循环本来就长期运行，
  默认预算会让合法程序误停；无人值守场景显式给 `--max-instructions`（或 `--timeout`）。
- 落地：
  1. `VMOptions.MaxInstructions`（`long`，`0` = 不限，默认）→ `VMBase` 在 `RunLoop`
     每条指令边界判断；**先判后扣**，`N` 恰好允许 N 条，第 N+1 条报错。
  2. 新错误类型 `RuntimeErrorType.InstructionBudgetExceeded`（追加在枚举末尾，不复用旧值）；
     错误走现有 `Run` 错误边界，自动回填 PC 与源位置。
  3. `IronRuntime.Run` / `RunModule` 新增 `maxInstructions` 参数（追加在末尾，不破旧调用）。
  4. CLI `run --max-instructions N`（四种输入均支持：`.st` / `.stmod` / `.stproj` / `.isb`）；
     非正整数或缺参数 → 退出码 1；超限 → 「运行时错误: [InstructionBudgetExceeded] …」+ 退出码 1
     （**不是**取消的 130）。帮助文本与 README 已同步。
  5. 与取消的分工写进 `VMOptions` 注释：取消 = 外部叫停（墙钟/ Ctrl+C，130），
     预算 = 确定性计数（可复现，1）。
- 实测：`WHILE TRUE` + `--max-instructions 1000` → 退出码 1，错误带
  `at 0x27` 与 `（…/hang.st:3）`；正常程序 + `--max-instructions 100000` → 输出 `3`、退出码 0。
- 测试：`VMInstructionBudgetTests` **5 例**（0=不限 / 恰好用完 / 越界 PC=2 / 死循环被叫停 /
  预算不是取消）+ `CliInstructionBudgetTests` **7 例**（退出码与错误文本 / 正常程序不受影响 /
  同预算两次错误完全一致（证明是计数不是墙钟）/ 非法值 0、-5、abc / 缺参数）。
  全量：**1919 通过 / 0 跳过 / 0 失败**。
- 性能说明：不限时热路径每指令只多一次 `long` 比较；本轮**未**做基准测试。
