- [x] **`REFERENCE TO` 前向引用**（2026-10-22 已修复，`590a008`）
  - 测试：`IronST.Frontend.Tests/ReferenceForwardDefectTests.cs`
  - `ReferenceToForwardTarget_ShouldBakeRealTargetType`（已解除 `Skip`）
  - 根因：F7 的类型布局不动点里**引用边不阻塞**（契约 M5 要求，引用型递归合法），
    于是引用目标在引用者被解析时仍是预声明占位符 `IECType.Void`
    → 永久烘焙 `REF_TO VOID` → 前向引用的字段访问一律报「结构体没有字段」
  - 修复：不动点收敛后做一次**回填**（`SemanticAnalyzer.BackfillReferenceTargets`）。
    结构体走「就地改字段字典」，符号表与代码生成侧类型表自动同步；数组元素类型
    需重建数组类型再写回字段。回填只改「指向谁」、不递归进目标结构体内部，
    因此互递归（A 引用 B、B 引用 A）不存在构造顺序依赖。
    `IECType` 新增 `ReferenceTargetName` 保留源码书写的目标名（占位符会丢名字）。
  - 验收：`ReferenceForwardDefectTests.cs` 9 项（前向 / 反向 / 互递归 / 自引用 /
    数组元素 / 嵌套结构体 / 表达式推导 / 未知目标仍报 E2015）+
    `BytecodeGen.Tests/ReferenceEndToEndTests.cs` 端到端 1 项
    （前向引用结构体走完 Frontend → IR → 字节码 → VM）

  - 根因（缺陷登记簿 §3.9）：不是「结果标签错成 `INT`」，而是**值转换缺失**，且分**三处**
    - 运算侧：`ExpressionEmitter.EmitBinaryExpr` 实数分支缺整数操作数提升
      → `sum / 2.0` 生成 `fdiv i16 %sum.ld, 2`，结果类型随左操作数退化为 `i16`
      （同文件 `EmitIntPower` **有**该转换，实数分支漏了）
    - 赋值侧：实数赋给整数未做截断 → `d := r`（`d: DINT` · `r: REAL`）得错值
    - **比较侧**（当时未登记）：`EmitComparison` 只按**左**操作数选指令，
      而后端 `IEQ`/`INE` 只比 `IntValue`、`FEQ` 只比 `FloatValue`
      → `5 = 5.0` 两个方向都得 FALSE
  - 边界：整数内部、实数内部的路径**都正确**；缺陷只在「整数 ↔ 实数」边界上
  - **非内存破坏**：VM 槽是统一 64 位、保留运行时 tag，IR 位宽只是建议值，
    位宽不匹配（`store i32 55` 写进 `alloca i16`）不会越界写，只影响值语义
  - 修复：运算侧 `PromoteToReal` + 赋值侧 `ConvertToTargetType` + 比较侧 `EmitComparison`
    统一到实数域；另补 `EnsureSameNumericDomain` —— 发射点当场断言
    「二元运算两操作数同域」，不再让非法 IR 流到后端
  - 验收：`NumericConversionEndToEndTests` **24 例**；
    字节码稳定性实测：不涉及跨界转换的程序**逐字节不变**（详见缺陷登记簿 §3.9.3）

    递归中表现为 `%n` 的 load 结果在 `CALL` 后继续参与 `IMUL`，`Fact(5)` 得 `16`。
  - 修复：新增 `FunctionLiveness` 做块级 SSA liveness，找出每个 `CALL` / 数学 `HCALL`
    之后仍活跃的指令结果；`FunctionEmitter` 为这些值分配稳定帧槽，
    **在定义处 `SETL` 写回**，调用后作废缓存，`EnsureReg` 按需 `GETL` 恢复。
  - 选择“定义处写回”而不是“调用前临时 PUSH/POP”：槽在定义支配的所有路径上有效，
    条件分支 / 合流不需要路径敏感的 spill；不改变 `SP`，也不影响栈参数布局与
    跨帧重定基常数。
  - 验收：`RecursiveFunction_ReturnsFactorial` 恢复并断言 `120`；
    `StackArgPassingTests.LoopCarriedAccumulator_IsPreserved` 移除 `Skip` 并通过；

  - 源码映射：spill 的 `SETL` / `GETL` 由 `EmitInstr` 的 `null → _currentSrc`
