# IronST 运行时与字节码简要参考（0.1.0）

> 从 `IronST.Runtime.Shared`、`IronST.Runtime`、`IronST.BytecodeGen`、`docs/stmod格式规范.md`、`docs/stmod链接协议.md`、缺陷登记簿（`A2/A8/A9/C1/C8` 等）整理。

---

## 1. VM 执行模型

- 栈式字节码 VM；寄存器从 `R8` 起，上限约 `250`（`[缺陷登记 C8]`：`_nextReg` 只增不减，已修为语句边界回收死值 + 临时寄存器安全回收，4 测试全绿，但通用回收仍未完全收敛）。
- 调用约定：`VMBase` 执行循环；`RunLoop` 每条指令边界检查取消状态与指令预算。
- 栈大小：默认 `8192`（`VMOptions` / CLI `--stack`）。
- 全局槽：标量 `1` 槽；聚合按 `FlatSlotCount` 展开（`A8` 修复）；数组全局的 IR 类型已改用语义层 `DeclaredType`。
- `StructHeap`：固定容量（默认 `100k`），`Alloc` 只递增 `_nextSlot`，无 `free`，只有 `Reset`（`[缺陷登记 C4]`：长跑不因只增不减耗尽，需明确上限与失败诊断或提供回收）。
- 线程安全：VM **非线程安全**；同一 VM 并发 `Run()` 无明确防护（`[缺陷登记 C3]`）。

---

## 2. 字节码文件 `.isb`

- 魔数：`IRST`（`0x49525354`）。
- 头部：版本、入口函数索引、结构体注册表（`StructRegistrations`）、全局初始化表、源位置映射。
- 加载校验：头部/版本/入口校验存在；无签名/沙箱；`[缺陷登记 C5]` 明确“字节码不是安全边界”，信任模型未落地。
- `.isb` 不是 `.stmod`：`.stmod` 魔数为 `STMD`，不可直接由 VM 执行（`run` 明确拒绝）。

---

## 3. 指令集（关键新增/扩展）

- `BOUNDS`（`0x94`，3 字节）：数组越界检查，越界抛 `ArrayBounds`（`C1` 修复）。
- `NULLCK`（`0x95`，2 字节）：引用解引用前检查 `Void`（空引用），抛 `NullReference`（`A2` 修复）。
- `GETGI` / `SETGI`：全局聚合读写（`A8` 修复）；注意不进 `GlobalIdx` 重定位表，含全局聚合动态访问的 `.stmod` 跨模块链接仍不可用（随 `B1`/`REL-3` 一起处理）。
- `SNEW` / `SSET` / `SGET`：结构体堆操作（`StructHeap`）。
- `HCALL`：宿主调用桥接（标准库、`Print`、数学函数、字符串函数）。

---

## 4. 运行时错误类型（已细分）

（完整定义见 `IronST.Common/Diagnostics/ErrorCode.cs` 及运行时枚举）

| 错误类型 | 典型触发 |
|---|---|
| `DivideByZero` | 整数/浮点除零 (`MOD` 除零同理) |
| `ArrayBounds` | 数组索引越界（`BOUNDS` 指令触发） |
| `NullReference` | 解引用未绑定的 `REFERENCE`（`NULLCK` 触发） |
| `StackOverflow` | 栈深度超限（VM 层未完全验收） |
| `SlotOverflow` | 寄存器/槽号溢出（`C8` 部分修复后普通规模已可过） |
| `TypeError` | 类型不匹配（如 `Void` 参与排序比较，`A10` 已修复为零值比较，不再抛） |
| `InstructionBudgetExceeded` | 指令预算超限（`C1` 新增，退出码 `1`） |

## 5. `.stmod` 链接协议（简要）

- `v1` 已实现：固定头（48 字节）、区段表（2 字节/条）、区段类型、元数据 Key、函数索引、编译产物的精确字节范围。
- 链接目标流程（`v1` 只实现前半段）：`.st` → `.stmod` → 多模块链接 → `.isb` → VM 执行。
- 链接未完成项（`B1`）：
  - `REL-6`、`REL-5`、`REL-1..6` 重定位表未完成；
  - `SYM-1/2/3`（符号解析）、`DG-1`（诊断）、`BUD-*`（预算）、`FMT-*`（格式）未完成；
  - `HOST-2`：CLI 与 IDE 的宿主函数 ID 映射不一致（顺序分配 vs 硬编码常量，`Ordinal` vs `OrdinalIgnoreCase`）；
  - `.stmod` 跨模块静态链接仍不可安全执行。
- `.stmod` 格式兼容策略（`B4`，`R12`）：旧制品遇到不兼容版本时应明确拒绝，避免“碰巧能跑/错绑”；策略未定稿。

## 6. 调试与监视

- 发布 VM（`Runtime`）与调试 VM（`Runtime.Debug`）分离；调试 VM 提供断点、单步、监视、PC→源行映射。
- IDE 调试：`VMDebugSession` 驱动（启动/暂停/单步/断点/读变量）；专用后台调试线程 + `AutoResetEvent` 信号 + `Dispatcher` 回主线程。
- 断点实现：源行→PC 映射（`AddAddressBreakpoint`）；`F9` 设置断点，`F10`（`StepOver`）、`F11`（`StepIn`，暂退化为 `StepOver`：`[模块 E]` 遗留）。
- 监视窗口（`WatchedGlobalSlots`）未接 UI（`[模块 E]` 遗留）。

## 7. 时钟源注入操作（A4 修复配套）

> 检查表 A4 要求：时钟源可注入（便于测试与确定性）。修复已在运行时层添加 `CLOCK` 接口（`HostCallIds.CLOCK = 0x000D`），不修改 VM 核心指令集，只通过宿主桥接注册。

### 注入方式（与 F13 浮点注入同源模式）

```csharp
// 在构造 VM 前，通过 DefaultHostEnvironment 或自定义宿主注入固定时钟
var bridge = new HostBridge();

// 默认实现（已在 DefaultHostEnvironment 注册，RegisterIfAbsent 允许覆盖）：
// 返回当前 UTC 毫秒时间戳（Int64，与 TIME 类型映射一致）。

// 测试时注入确定性时钟（示例）：
bridge.RegisterIfAbsent(HostCallIds.CLOCK, ctx =>
{
    // 固定返回 2026-01-01 00:00:00 UTC 的毫秒时间戳（用于确定性测试）
    return new BcValue(1735689600000L);
});

// 构造 VM 时传入已注册的桥接
var vmOptions = new VMOptions { HostBridge = bridge };
```

### 验收点

- 编译期：`TIME` 字面量解析为 `i64` 占位（已存在，`TimeLiteralParserTests`）。
- 运行期：`CLOCK` 宿主函数可被覆盖（`RegisterIfAbsent` 保证不覆盖用户显式注册）；默认实现返回 `DateTimeOffset.UtcNow.ToUnixTimeMilliseconds()`。
- 测试：可注入固定值后，`TOD#`、`DT#` 相关运行时行为可确定性断言（无需依赖系统时钟）。
